## 0. Hedef ve dilimleme

**Hedef (tam handoff):** İki aşamalı sihirbaz drawer — (1) Ayarlar: kapsam (tek/kademe/tümü) + optimizasyon
ağırlıkları + katı mod, (2) Üretiliyor → Sonuç: çoklu aday taslak (skorlu) / toplu özet → "Editörde Aç"
(taslağı editöre yükler, **yayınlamaz**). Çözüm bulunamadı durumu + kısıt-gevşetme.

**İki yürütme dilimi (kullanıcı onaylı):**
- **Dilim 1 (BU döngü):** solver **motoru** (ağırlıklı skorlama + katı mod + **3 aday**) + **tek-sınıf** tam
  sihirbaz UX (ayarlar/üretiliyor/3-aday-sonuç/çözüm-yok/büyük-önizleme/Editörde-Aç). Üret→seç→uygula akışı.
- **Dilim 2 (sonraki döngü):** **kademe/tümü** çok-sınıf **global** üretim + toplu-sonuç satırları, aynı
  motorun üzerine. (Çapraz-sınıf öğretmen çakışması = global problem; motor tek-sınıfta kanıtlandıktan sonra.)

Her dilim ger­çek çalışır (mock yok), kendi spec/plan/review döngüsüne sahiptir. Bu doküman **Dilim 1**i detaylandırır;
Dilim 2 kapsam-dışı (aşağıda işaretli).

> **Risk notu (port'la yönetilir):** Özel sezgisel solver tek-sınıf için uygun; global çok-sınıf (Dilim 2)

## 3. Solver mimarisi (saf, test edilebilir)

### 3.1 Portlar (Application)
- **`IScheduleSolver`**: `SolveResult Solve(SolveInput input)` — **saf**, DB yok.
- **`IAvailabilityProvider`**: `IReadOnlySet<TimeSlot> BlockedSlots(Guid teacherId)` — no-op (boş).

### 3.2 SolveInput
- `LessonDemand[]` — yerleştirilecek dersler (müfredat saati × {SubjectId, TeacherId, IsBlockMember, BlockGroupKey?}).
- `TimeSlot[]` AvailableSlots (zil-grid Lesson period'ları).
- `OccupiedSlot[]` ExternalOccupancy (bu program hariç dönemdeki aktif öğretmen/derslik dolulukları).
- `HomeRoomId`, `BellCapacity` (gün×period).
- **`SolverWeights`** = `{ MorningHardSubjects: Low/Mid/High, MinimizeGaps: Low/Mid/High, DailyBalance: Low/Mid/High, KeepBlocks: bool }`.
- **`bool StrictMode`** — true ise hiçbir soft ödün yok; tam feasible çözüm yoksa **nosolution**.
- **`int CandidateCount`** = 3.

### 3.3 SolveResult
- `Candidate[] Candidates` (≤3) — her biri: `Placements[]` + **metrics** `{ ConflictCount(0=feasible), MissingHours, AvgTeacherGap, PreferencePercent, DailyBalanceLabel, Score }` + `IsRecommended`.
- `bool NoSolution` (strict + feasible-yok) + `RelaxationHint[]` (hangi kısıt gevşetilirse).
- Adaylar **çeşitlilikli**: 3 farklı deterministik strateji (ör. sabah-öncelikli / pencere-azaltan /
  denge-öncelikli) → farklı soft-trade-off noktaları. Ağırlıklar skorlamayı yönlendirir.

### 3.4 Saf birimler (plan TDD ile böler)
`BuildLessonDemands` · `SlotFeasibility` (her katı kısıt ayrı; müsaitlik no-op) · `OrderByMostConstrained` ·
`BacktrackingSolver` (forward-checking + deterministik düğüm/süre bütçesi → asılı kalmaz; bütçe aşımı veya
strict-infeasible → nosolution/kısmi) · `CandidateStrategies` (3 strateji) · `ScoreCandidate` (ağırlıklı soft
metrikler → Score + alt-metrikler) · `RelaxationHints` (strict-nosolution'da en kısıtlayıcı soft kuralları öner).

## 4. Akış (üret → seç → uygula)

```
İdareci Draft programda "Otomatik Oluştur" → sihirbaz (ayarlar)
 → EnqueueAutoGenerate(programId, weights, strict): job satırı (Queued) + Hangfire enqueue → jobId
 → AutoGenerateScheduleJob: tenant set → girdi topla → IScheduleSolver.Solve(3 aday) → adayları job'a JSON sakla → Done | NoSolution
 → FE poll GetAutoGenerateStatus(jobId): Running → Done(adaylar+metrik) | NoSolution(hint)
 → idareci bir adayda "Editörde Aç" → ApplyAutoGenerateDraft(jobId, candidateId):
      hedef programın aktif (draft) yerleşimlerini temizle (occupancy release) → adayın yerleşimlerini uygula
      (occupancy reserve + DB filtreli unique index backstop) → program Draft kalır
 → FE editöre yönlendir (/admin/schedule/:id/edit) — idareci ince ayar + yayın
```

- **Hedef:** tek sınıfın `ScheduleProgram`'ı; **Published'a autogen yok** (yalnız Draft/Revising).
- **Üret≠uygula:** job yalnız adayları üretir/saklar; **uygulama** kullanıcı "Editörde Aç" deyince olur (seçilen aday).
- **İzin:** `timetable.manage` (yeni izin yok).

## 5. Backend dilimleri (Dilim 1)

- **Persistence:** `schedule_generation_jobs` (`[academic]`): `{ Id, SchoolId, ProgramId, Status(Queued/Running/Done/NoSolution/Failed), Weights(JSON), Strict, CandidatesJson (≤3 aday: placements+metrics), FailureReason?, CreatedAt, CompletedAt }`. TenantEntity + migration. (Adaylar JSON snapshot — `ScheduleVersion` snapshot deseni gibi.)
- **CQRS:** `EnqueueAutoGenerateCommand` (doğrula: program Draft/Revising + sahiplik) · `GetAutoGenerateStatusQuery` (scope) · `ApplyAutoGenerateDraftCommand(jobId, candidateId)` (job Done + aday var → programa uygula; domain `ApplyGeneratedDraft` metodu netleşir).
- **Hangfire `AutoGenerateScheduleJob.RunAsync(jobId, schoolId, programId)`:** SetForLoginFlow → Running → girdi topla (görevlendirme + `IRequiredHoursResolver` + bell + external occupancy + ev-dersliği) → `Solve` → CandidatesJson + Done | NoSolution | Failed.
