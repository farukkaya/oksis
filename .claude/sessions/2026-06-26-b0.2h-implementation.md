# 2026-06-26 — B0.2H: Level-based weekly hours (implementation)

Ayarlar bug-cleanup item **B0.2H**: wire the Ders Kataloğu weekly hours to the
existing level-based model (Option A) instead of a single `recommendedWeeklyHours`
field. Plan: `2026-06-26-b0.2h-plan.md`. TDD throughout; Chrome DevTools E2E; docs.

## Approach (user-approved)
- **Model:** existing `CurriculumHourTemplate` (MoNE master, version `2025.04`) +
  `SchoolWeeklyHourOverride` (tenant + season override) + `RequiredHoursResolver`.
  **No new `SubjectGradeLevel.WeeklyHours` column** (would be a 3rd conflicting source).
- **Key architectural point:** Subject is GLOBAL master; weekly hours are TENANT +
  SEASON override → hours editing is a SEPARATE save from the subject's (global) save.
- **UX (chosen):** per-level table inside the Ders Düzenle drawer with its own
  "Saatleri Kaydet"; new subject = 2-step (save subject first → then hours). List
  column shows effective min–max range ("4–6 sa").
- **Reconcile:** effective target == MoNE default (master ?? 0) → delete override
  (revert to default); else upsert. Season null → active season (holidays pattern).
