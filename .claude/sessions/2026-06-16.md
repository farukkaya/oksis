# Session 2026-06-16 — Ders Programı: Multi-Draft Model + Auto-Generate Header Flow

## Context / how it started
User asked whether the code was developed enough to run `OKSIS-Faz3-Otomatik-Uretim-Test-Rehberi.docx`. It was (backend+frontend complete for the row-menu/program-based flow). But the user then said the "Otomatik Oluştur" trigger was misplaced (should be a Hub-header button, not the row ⋯ menu), and that auto-generate should generate **from scratch** and save a **new Draft**, not apply to an existing program. Brainstorming uncovered that this requires a program-model rework.

## Design decisions (binding) — see `.claude/specs/ders-programi-cok-taslak-otomatik-uretim-design.md`
- **K1/K9** One **live** program (Published OR Revising) + unlimited **Draft** per class+term. Program unique index filtered `status >= 1`.
- **K2** `CreateProgram` no longer rejects a second program for a class+term.
- **K3/K10** Publish-swap: publishing demotes the existing live sibling (Published/Revising) to Draft (kept), then publishes. Restore-version does the same (A10).
- **K8/K12** Resource reservation (teacher/room/class-slot uniqueness) applies only to **live** placements — denormalized `LessonPlacement.IsReserving`; the 3 placement unique indexes filter `AND is_reserving = 1`. Drafts overlap freely; conflicts caught at publish / via occupancy precheck (reserving placements of OTHER branches).
- **K11** First saved edit to a Published program → Revising.
- Auto-generate is class-based & from-scratch: header trigger; `schedule_generation_jobs` keyed by branch+term+year; apply creates a NEW Draft and returns its id; new `GET auto-generate/classes`.
