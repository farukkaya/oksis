## Context / decisions

Started from Faz 2.5A (temporary-change backend, `ScheduleException`, P24–P27) already done. Goal was the temporary-change **web UI** (closing Debt-FE-5). Brainstorming surfaced two things that reshaped the work:

1. **Design ↔ backend model mismatch.** The handoff (`schedule_publish.jsx`) modelled "Geçici değişiklik" as a whole-program publish-type toggle (just a date). The 2.5A backend is per-placement exceptions (Cancellation / TeacherSubstitution / RoomChange), `targetPlacementId` from the published snapshot, one exception per call, required reason, no move/add/TimeChange.
2. **Editor auto-save was wrong vs design.** The existing editor wrote every drag/drop to the server immediately; the design has a buffered **Kaydet** button (disabled when clean, dirty-dot when changes). User requested the buffered model. Key reassurance: consumers read only the published snapshot, so edits never reach users until publish — no extra work needed for that.

This split the work into 2.5B-1 (editor buffered save) then 2.5B-2 (temporary change). User dropped an earlier "allow conflicts at save, block only at publish" request (out of scope; conflict model stays strict). For 2.5B-2 the user first wanted editor-diff→exceptions, but after the buffered model + backend constraints made that constraint-heavy (published-only, 3 types, one-type-per-placement, single-weekday), the user chose the **drawer compose form** (1:1 with backend).
