# Session — 2026-06-06

## roles-permissions ISSUE-06 — ExpireRoleAssignmentsJob (oksis-api)

Implemented the daily Hangfire sweep that expires time-limited role assignments and
drops the affected users' permissions. The issue's "sync drift" warning was confirmed:
`RoleAssignment` had no `ValidUntil` / `Expire()` / `Expired`, so the prerequisite domain
extension was included in this issue (the issue text allowed this).

### What changed
- **Domain (Users module):** `RoleAssignment.ValidUntil` (nullable, UTC), `RoleAssignmentStatus.Expired` (=3),
  `RoleAssignment.Expire(now)` (Active→Expired only, raises `RoleAssignmentExpiredEvent`),
  optional `validUntil` param on `Create(...)`. Tightened `Reactivate()` to reject the
  terminal `Expired` state (was implicitly allowed via `!IsActive`).
- **Persistence:** `valid_until` column + status check constraint now `('Active','Inactive','Expired')`;
  migration `20260606_add_role_assignment_valid_until`.
- **Job:** `ExpireRoleAssignmentsJob` mirrors `ExpireStaleInvitationsJob` — one deliberate
  `IgnoreQueryFilters()` to find candidate schools, then `SetForLoginFlow` per school so the
  query filter + interceptor re-scope each tenant. Per affected person:
  `IPermissionCacheBuilder.InvalidateAllForPersonAsync` + one per-school
  `IPermissionVersionBumper.BumpForPersonsAsync(revokeSessions: false, ...)`.
  Idempotent (Active guard). Structured logging (counts/SchoolId, no PII).
- **DI:** scoped registration; recurring (cron) trigger deferred to Api host wiring (same as sibling jobs).

### Key decision (from the review)
`revokeSessions: false` for automatic expiry vs `true` in `RevokeRoleAssignmentCommandHandler`
(admin/emergency revoke). Automatic time-expiry isn't an emergency: a perms_ver bump makes the
old access token stale → silent refresh → expired role drops, while the user's other roles keep
their sessions (no full logout). Meets AC "yetki sonraki istekte düşer."
