## ISSUE-06 — Invitation Lifecycle (commit `Issue #6 …`)
- **Domain:** new `Invitation` AR state machine (`Create`/`MarkSent`/`MarkOpened`/`Accept`/`Expire`/`Revoke`/`Resend`). `Created→Sent→Opened→Accepted`; active→`Expired`/`Revoked`. `IsActive => Status ∈ {Created,Sent,Opened}`. Only `TokenHash` (SHA-256) persisted; plain token flows **only** via `UserInvitedEvent` payload (never a property). `Resend` rotates token hash + renews expiry + `RetryCount++` + resets to `Created`. Events: `UserInvitedEvent`/`InvitationOpenedEvent`/`InvitationExpiredEvent`/`InvitationRevokedEvent`.
- **Persistence:** `users.invitations`; `token_hash` **global** unique `ux_invitation_token_hash` (cross-tenant), plus school/status, school/person/season, school/batch (filtered) indexes + status check. Migration `20260530161622_…`. DbSet wired.
- **API (`UserInvitationsController`, `api/v1/users/invitations`):** GET (paged, status/season/batch), POST (201), POST `bulk` (202 batchId+totalQueued, max 500), POST `{id}/resend`, POST `{id}/revoke` (204), GET `by-token/{token}` (**anonymous**, token-less preview, IgnoreQueryFilters). Writes → `users.invite` (revoke → `users.revoke-invite`); reused existing perms (no new seed). by-token: `TenancyMode.Optional` + `[AllowAnonymous]`.
- **Codes:** `USERS_INVITATION_ACTIVE_EXISTS` (409), `_EXPIRED` (410 via by-token), `_TOKEN_INVALID` (404), `_ALREADY_ACCEPTED` (409), `_NOT_FOUND` (404), `_INVALID_STATE`/`_PERSON_INVALID_STATE` (400). ResultExtensions USERS_INVITATION_* mapping added (410/404/409 special-cased before generic).
- **Expiry sweep:** `ExpireStaleInvitationsJob` flips only active+stale → Expired (skips Accepted/Revoked); per-school flush (sets tenant context); `TimeProvider` injected for testable cutoff. Recurring host wiring deferred (no Hangfire RecurringJob host yet; in-process fallback).
- **Decisions/deviations:** active-uniqueness enforced in app (SQL Server filtered index can't `OR`/`IN` on status) — token-hash uniqueness is the DB constraint; events published but actual notification dispatch + accept/account flow out of scope; `MarkOpened`/`Accept` domain methods exist (state-machine completeness) but no endpoint (belong to onboarding); new controller named `UserInvitationsController` to avoid clash with legacy `InvitationsController` (`api/v1/invitations`).
- **Tests:** Domain 190 (+17), Application 510 (+29), Api 70, Tests 22, Integration 72 (+3). All green. Integration covers real-SQL active-duplicate 409, token-hash global unique violation, sweep-only-active.

## Gotcha for next time
- `InvitationChannel`/`InvitationStatus`/`ConsentType` exist in **both** `Modules.Identity.Enums` and `Modules.Users.Enums`; files importing both (e.g. for `PortalType`/`UserRole`) need a `using X = Oksis.Domain.Modules.Users.Enums.X;` alias.
- SQL Server filtered unique indexes don't support `OR`/`IN` in the WHERE predicate — enforce "unique among status ∈ {a,b,c}" in the handler; rely on a simpler DB constraint (token hash, (person,type,version)) for the hard guarantee.
- `NationalId.Hash` is `byte[]` → EF can't translate `List<byte[]>.Contains(column)`. Convert tenant hashes to hex and compare in memory.
- Cross-module enqueue: define an interface in Application (e.g. `IImportProcessor`), implement the Hangfire/in-process job in Infrastructure, enqueue `Enqueue<IInterface>(...)` — keeps Application free of the job type.
- For per-row transaction isolation in a job, depend on `OksisDbContext` directly (Infrastructure) and `ChangeTracker.Clear()` after a failed row so the failed Added entity doesn't carry into the next row's SaveChanges.
- `IAccountProvisioner`/`InvitationAccountProvisioner` is the identity-account boundary for invitation accept (chosen password, no temp-password/welcome) — distinct from `ICreateUserService` (admin create).
- `dotnet format Oksis.slnx` reformats the **whole** solution (touched ~20 unrelated files); had to `git checkout` the collateral to keep the issue commit clean. Scope `dotnet format` with `--include <path>` for single-file fixes.
- MockQueryable `BuildMockDbSet()` must be assigned to a local **before** `.Returns(...)` — building substitutes inside `Returns()` corrupts NSubstitute's call queue.
